2、ConcurrentHashMap 是 线程安全的 Map。在多线程环境下（比如 Netty 的多个 IO 线程同时读写在线玩家表），它能保证 并发读写不出错，而且性能比用 synchronized 的 HashMap 更好。这里它用于保存在线玩家映射（playerId -> Channel），确保登录/掉线/推送时的并发访问安全
3、存在一个隐患： 如果我在Redis里存了消息，还没推给玩家，服务器突然宕机了怎么办？ 或者 推给玩家了，但玩家网络波动没收到包怎么办？

使用大厂的 “消息可靠性投递” 机制（QoS）：
序列号 (SeqId)：每条消息都有一个递增 ID。
确认机制 (Ack)：服务器发给客户端消息后，不立即删 Redis。只有客户端回传一个 ReqChatAck(seqId)，服务器才去 Redis 删掉这条消息。
重试：如果没有收到 Ack，下次心跳包或者登录时再发一次。
